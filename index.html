Decision Trees & Impurity Metrics

This lab centered around the mathematics governing Decision Tree splits. I coded information gain criteria from scratch to evaluate split quality.

  • Gini Impurity: Wrote a pure Python loop to calculate Gini equations for both binary and multi-class target arrays.
  • Information Gain: Implemented information_gain(parent, children) to mathematically determine the optimal node split during tree construction.
  • Tested the raw mathematical logic against specific boolean arrays (e.g., verifying that a perfectly split [0,0,1,1] array yields a max Gini impurity of 0.5).
# Gini Impurity (works for binary & multi-class) def gini_impurity(y): n = len(y) if n == 0: return 0.0 counts = {} for label in y: counts[label] = counts.get(label, 0) + 1 gini = 1.0 for count in counts.values(): p = count / n gini -= p * p return gini # Information Gain using Gini impurity def information_gain(parent, children): n_parent = len(parent) if n_parent == 0: return 0.0 parent_impurity = gini_impurity(parent) weighted_child_impurity = 0.0 for child in children: weight = len(child) / n_parent weighted_child_impurity += weight * gini_impurity(child) return parent_impurity - weighted_child_impurity # --- TEST CASES --- print("Gini([0,0,0,0,0]) =", gini_impurity([0, 0, 0, 0, 0])) print("Gini([0,0,1,1]) =", gini_impurity([0, 0, 1, 1])) print("Gini([0,1,2]) =", gini_impurity([0, 1, 2]))

Bayesian Probability & Medical Diagnostics

Moving into probabilistic modeling, this notebook applied Bayes' Theorem to understand diagnostic reliability in healthcare scenarios.

  • Programmed the Bayesian mathematical formula to evaluate $P(\text{Disease} \mid \text{Test}^+)$.
  • Visualized the fundamental flaw of "base-rate neglect" by plotting how the reliability of a positive test dramatically shifts as the underlying population prevalence ranges from a rare 0.1% to a common 50%.
""" Exercise 7.15: Implement Bayes' theorem for medical diagnosis. Plot how P(Disease|Test+) varies as prevalence ranges from 0.1% to 50%. """ import numpy as np import matplotlib.pyplot as plt # Given test characteristics sensitivity = 0.90 # P(Test+ | Disease) specificity = 0.90 # P(Test- | No Disease) false_positive_rate = 1 - specificity # Prevalence range: 0.1% to 50% prevalence = np.linspace(0.001, 0.5, 500) # Bayes' theorem computation # P(Disease | Test+) = (Sens * Prev) / (Sens * Prev + FPR * (1 - Prev)) posterior = (sensitivity * prevalence) / ( sensitivity * prevalence + false_positive_rate * (1 - prevalence) ) # Plotting the Posterior Probability plt.figure() plt.plot(prevalence * 100, posterior * 100) plt.xlabel("Disease Prevalence (%)") plt.ylabel("P(Disease | Test +) (%)") plt.title("Effect of Prevalence on Posterior Probability") plt.grid(True) plt.show()

My Project: Spaceship Titanic (Machine Learning)

Domain Understanding

The Spaceship Titanic was an interstellar passenger liner launched in 2912. During its voyage to transport roughly 13,000 emigrants from our solar system to three newly habitable exoplanets, it collided with a spacetime anomaly hidden within a dust cloud.

Though the ship remained intact, almost half of the passengers were mysteriously transported to an alternate dimension. The core objective of this predictive modeling project is to rescue the lost passengers by predicting exactly which individuals were transported by the anomaly using records recovered from the spaceship's damaged computer system.

Data Preprocessing & Group-Based Imputation

Standard data imputation usually fills NaNs with global means or medians, which destroys data nuance. I transitioned to a far more sophisticated Group-Based Deterministic Imputation strategy:

  • Group Linking: Passengers traveling together share identical `GroupId` prefixes. If one passenger's HomePlanet or Destination was missing, the algorithm dynamically searched for the most common mode within their specific group and assigned it.
  • Cabin Interpolation: Missing cabin numbers were assigned using the median cabin number of their respective group, physically placing them close to their family on the ship.
  • Log Transformations: Financial spend columns contained massive right-skewed outliers. I applied np.log1p() across all spending metrics to compress the variance, making the data highly interpretable for linear meta-models.

Analytical Insights & Data Relationships

  • The Zero-Spend Phenomenon: Plotting the distribution of the target variable against financial features revealed that passengers with exactly zero total spend were overwhelmingly "Transported". This perfectly correlated with the CryoSleep status.
  • Family Survival Rates: Analysis of the PassengerId prefix (Group ID) showed that survival/transportation was not randomly distributed. Entire family groups tended to share the exact same fate.
  • Cabin Side Impact: Parsing the cabin strings showed that passengers on the Starboard (S) vs. Port (P) side of the ship experienced distinct anomaly impacts.

Advanced Feature Engineering

To provide the ensemble models with granular decision boundaries, the initial 14 features were engineered and expanded into over 40 structured columns:

  • Group Dynamics: Derived GroupSize, FamilySize (via Surname mapping), and a boolean Solo traveler flag.
  • Spatial Engineering: Split Cabin into Deck, Num, and Side. Created a new CabinZone feature using quantile binning (qcut) to map longitudinal ship sections. Combined categories to create HomeDest (HomePlanet + Destination) and DeckSide.
  • Age Bracketing & Interaction: Created explicit flags for IsChild (under 13), IsTeen, and IsSenior. Built an interaction feature (AgeSpendInteraction) multiplying Age by the Log Total Spend to capture demographic financial behavior.
  • Spend Ratios: Created AvgSpendPerService and SpendPerGroupMember to capture financial density relative to group size.

Feature Importance Insights:

Model Evolution: The Journey to ~82%

The architecture evolved significantly over weeks of continuous experimentation, learning from each plateau to push the boundaries of accuracy.

Phase 1: The 80.7% Baseline (Diverse Soft-Voting)

I started with a Soft-Voting Ensemble prioritizing mathematical diversity, combining LightGBM (Tree-based), an MLP Classifier (Neural Net), and an SVC (Geometric mapping).
Why it plateaued: Both MLPs and SVMs are notoriously sensitive to extreme financial outliers. Even with a RobustScaler, the massive variance in TotalSpend caused the neural network to memorize noise rather than broad survival patterns, capping the accuracy at 80.7%.

Phase 2: The 81.4% Breakthrough (XGBoost + SMOTE)

Realizing the sensitivity of Neural Nets, I pivoted to a highly tuned, standalone XGBoost model paired with SMOTE (Synthetic Minority Over-sampling Technique) to balance the target classes.
Why it worked: By heavily turning up XGBoost's L1/L2 penalties (alpha=4.59, lambda=3.05) and keeping the tree depth shallow, the model was forced to generalize. SMOTE helped define the minority class boundary.
The Limitation: Tree models inherently overfit synthetic data eventually. While SMOTE pushed the score to 81.4%, the synthetic variance prevented the model from capturing the hyper-specific relational logic of the passenger families.

Phase 3: The ~82.0% Advanced Stacking Ensemble (Current)

To shatter the 81.4% ceiling, I abandoned SMOTE and synthetic data entirely. Instead, I combined the new Group-Based Imputation and Log Transformations with a massive Multi-Seed, 5-Fold Stratified Stacking Ensemble.

  • The Base Learners (Level 0): I deployed five drastically different, highly-regularized algorithms: ExtraTrees, HistGradientBoosting, XGBoost, LightGBM, and Native CatBoost.
  • The Meta-Model (Level 1): The Out-Of-Fold (OOF) probability predictions from all five base models were stacked together and fed into a LogisticRegression(C=1.0) meta-model.

Why this is the ultimate architecture: Rather than forcing one model to learn everything, the linear meta-model mathematically learned exactly which base algorithm to "trust" under different conditions, providing immense predictive stability and pushing the final accuracy to the ~82% threshold.

# The final confidence matrix combines the Meta-Model and Simple Averaging best_oof = weight * stack_oof + (1.0 - weight) * simple_oof

Threshold Optimization & Group Rules

The most advanced part of this architecture happens after the models output their probabilities. By analyzing the raw predictions, I applied dynamic Thresholding and Group Post-Processing to drastically boost test performance:

  • Threshold Tuning: Instead of assuming a 0.5 probability cutoff, the system iterates from 0.35 to 0.65 to find the mathematical threshold that maximizes accuracy on the validation set.
  • Test Group Rules Override: If an entire family/group is predicted to survive, but one member's probability is hovering near the threshold of uncertainty, the algorithm mathematically "pulls" that member's probability toward the group majority, mimicking the reality that families stayed together during the disaster.

Conclusion & Key Takeaways

This project was a masterclass in advanced tabular data science. The biggest lessons learned were:

  • Ensembling > Individual Models: Stacking predictions from HistGBM, ExtraTrees, LightGBM, XGBoost, and CatBoost into a Meta-Model provided an incredibly stable foundation immune to singular model variance.
  • Group Dynamics are Crucial: Implementing custom functions to dynamically adjust uncertain predictions based on the fate of a passenger's family group (Group Post-Processing) yielded massive gains over standard independent row predictions.
  • Data Preprocessing is Everything: Using group medians to impute missing values and applying Log Transformations to massive spend outliers proved far superior to standard statistical imputation.
